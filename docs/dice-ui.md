# GUI проверки D20

`ui.dice()` или `ui.dice(color)` создаёт компонент, но не открывает GUI. До вызова `roll()` кубик
статичен и по умолчанию расположен по центру родительского контейнера.
Компонент также доступен через `ui.create("dice")`. Все необходимые текстуры включены в мод.

## Использование

Готовый скрипт: [examples/dice-check.js](examples/dice-check.js).
Назначьте его игроку, чтобы `c.getSubject()` был игроком.
Пример не создаёт кнопку: вызовите `roll(c)` из своей логики, когда нужно начать бросок.

```javascript
function main(c)
{
    var ui = mappet.createUI(c, "handler");
    var diceColor = c.getSubject().getStates().getString("dice_color");

    // Только статичный кубик, его блоки и подложка. Без кнопки.
    ui.dice(diceColor).difficulty(15).base(5).id("dice"); // 240×300 GUI-пикселей.

    c.getSubject().openUI(ui);
}

// Вызывается вашей логикой, когда GUI уже открыт.
function roll(c)
{
    var context = c.getSubject().getUIContext();

    // Миллисекунды, сложность, исходный результат D20, основа.
    context.get("dice").roll(2400, 15, 12, 5);
    context.sendToPlayer();
}

function handler(c)
{
    var context = c.getSubject().getUIContext();

    if (context.getLast() === "dice")
    {
        // Штатное событие GUI, как у кнопки. Отдельный callback не нужен.
        var data = context.getData();
        var total = data.getLong("dice.total");       // 17
        var outcome = data.getString("dice.outcome"); // "success"
        var skipped = data.getBoolean("dice.skipped");

        c.send("Результат: " + total + ", исход: " + outcome
            + (skipped ? " (анимация пропущена)" : ""));
    }
}
```

`difficulty(value)` и `base(value)` принимают целые числа от 0 до 99.
`base()` теперь показывает блок «Параметр и навык»; название метода сохранено.
`roll(durationMs, difficulty, result, base)` принимает исходный результат от 1 до 20,
проверяет аргументы и обновляет оба боковых блока. Сам бросок определяет ваш скрипт;
компонент показывает переданное число, а не генерирует случайное.
Обычная сумма также должна быть не больше 99: трёхзначные значения отклоняются
до изменения компонента, а не обрезаются. Для критических 1/20 основа не прибавляется.

### Цвет кубика

```javascript
var color = c.getSubject().getStates().getString("dice_color");
var dice = ui.dice(color); // Например, значение стейта — "blue".
// Или явно: ui.dice("blue"). Без аргумента — original.
// После создания: dice.variant("green").
```

Поддерживаются `original`, `blue`, `burgundy`, `green`, `purple`, `red`, `violet`,
`yellow`. Аргумент — обычная строка: литерал, переменная или результат чтения стейта.
Пустая строка и `null` выбирают `original`; пробелы и регистр нормализуются.
Неизвестное имя вызывает понятную ошибку. Выбор касается только кубика,
не меняя золотой/красный цвет результата. Изменение `variant()` не перезапускает бросок.

Задайте `id("dice")`, чтобы получать событие завершения и менять компонент после
открытия GUI. Обновления из обработчика GUI отправляются штатным механизмом Mappet.
При изменениях из другого скрипта вызовите `context.sendToPlayer()`.

## Последовательность и результат

1. Вращение нужное число полных циклов, затем остановка и статичный кубик.
2. Анимация исходного числа поверх кубика: золотое при `result >= difficulty`,
   иначе красное.
3. Копия числа основы вместе с плюсом плавно перелетает к кубику за 600 мс.
   Исходный блок основы остаётся на месте.
4. На кубике заново проигрывается анимация суммы `result + base`.
   Цвет определяется по `sum >= difficulty`.
5. Под кубиком проигрывается соответствующая надпись результата.
6. После её последнего кадра отправляется одно событие GUI с ID кубика.
   Итоговое число и надпись остаются видимыми.

Натуральная **1** — всегда критический провал, красное число 1.
Натуральная **20** — всегда критический успех, золотое число 20.
В обоих случаях основа не прибавляется, перелёт и анимация суммы пропускаются,
сложность не влияет на исход. Надпись критического результата и событие остаются.

После запуска броска **ЛКМ в любом месте открытого GUI** немедленно показывает
окончательные число и надпись и отправляет то же событие один раз.
Этот клик не нажимает кнопку под курсором. До запуска и после завершения
кубик клики не перехватывает. ПКМ анимацию не пропускает.

`reset()` отменяет бросок без события завершения и возвращает статичный кубик без
результата и надписи; боковые блоки остаются. Новый `roll()`, в том числе с теми
же параметрами, запускает последовательность заново.

## Данные события

Пример ниже использует ID `dice`; при другом ID префикс меняется.

| Ключ | Чтение | Значение |
| --- | --- | --- |
| `dice` | `getInt` | Счётчик завершённых бросков |
| `dice.sequence` | `getLong` | Номер команды запуска |
| `dice.result` | `getInt` | Исходный D20 |
| `dice.total` | `getLong` | Сумма либо исходная 1/20 для критического исхода |
| `dice.difficulty` | `getInt` | Сложность из вызова `roll` |
| `dice.base` | `getInt` | Основа из вызова `roll` |
| `dice.success` | `getBoolean` | Успех с учётом критических исходов |
| `dice.critical` | `getBoolean` | Выпала 1 или 20 |
| `dice.outcome` | `getString` | `success`, `failure`, `critical_success`, `critical_failure` |
| `dice.skipped` | `getBoolean` | Анимация завершена нажатием ЛКМ |

Параметры результата фиксируются при запуске: изменение видимого `difficulty()`
или `base()` во время броска не меняет его итог. Для совместимости данных события
сумма по-прежнему хранится как `long`, хотя новая раскладка поддерживает только две цифры.

## Время и масштаб

Первый аргумент `roll()` сохраняет старую логику: это запрошенное время
**вращения вместе с остановкой**, без последующих эффектов результата.
Для встроенных текстур цикл вращения — 400 мс, остановка — 1600 мс.
Вращение занимает `max(0, durationMs - 1600)`, округлённое вверх до 400 мс.
Даже `roll(0, ...)` проигрывает полную остановку.

Например, `roll(2400, ...)` — два цикла вращения и остановка, всего 2400 мс.
Обычная проверка затем занимает ещё 2100 мс: число 500, перелёт 600,
сумма 500, надпись 500. Критическая — ещё 1000 мс: число и надпись.
`roll(2500, ...)` округляет время кубика до 2800 мс.
Отрицательное время отклоняется.

Длительности кадров чисел, надписей, вращения и остановки читаются из
`.png.mcmeta` штатным парсером Minecraft; один тик — 50 мс.
При замене ассетов меняются и длительности соответствующих фаз.
Каждый кубик имеет независимый клиентский таймер, обновления с сервера на каждый
кадр не нужны. При низком FPS время сохраняется, промежуточные кадры могут пропускаться.

### Границы панели

`dice.wh(width, height)` теперь задаёт **размер всей панели**: кубика,
сложности, основы, перелёта, числа результата, надписи и подложки.
Это изменение относительно первой версии, где размеры относились только
к кубику, а боковые элементы рисовались за его границами.

По умолчанию панель — **240×300 GUI-пикселей**, с полупрозрачной чёрной подложкой.
При фактическом масштабе GUI 2 это 480×600 физических пикселей — размер нового макета.
Вся сцена равномерно масштабируется внутри её прямоугольника, сохраняя пропорции;
свободное место в квадратной или вытянутой панели остаётся подложкой.
Рисование дополнительно ограничено её границами штатным механизмом отсечения
McLib, с учётом отсечения родительского контейнера.
Размеры больше не подгоняются под весь экран: смена разрешения или положения
панели не меняет её внутренний масштаб при неизменных `wh`.

```javascript
var dice = ui.dice().difficulty(20).base(10).id("dice");
dice.wh(240, 300); // Холст 240×300; сам кубик 112×112 GUI-пикселей.
dice.wh(480, 600); // Холст 480×600; сам кубик 224×224 GUI-пикселей.
dice.wh(300, 300); // Холст 240×300 внутри квадратной панели, поля по 30 слева/справа.
```

Полная композиция построена относительно макета **480×600**. Масштаб равен
`min(width / 480, height / 600)`. Все слои используют один и тот же прямоугольник
и накладываются друг на друга без ручного размещения отдельных блоков.
Положение самого кубика задано в ассетах; компонент центрирует всю панель.
Необязательно рисовать рамку: прямоугольная
подложка показывает реальные границы компонента.
`dice.background(argb)` меняет её цвет и прозрачность, `dice.background(0)`
отключает подложку. Это не меняет затемнение остальных частей экрана.

Пиксели здесь — **GUI-пиксели Minecraft**, как у остальных компонентов Mappet,
а не обязательно физические пиксели скриншота. Физический размер зависит от
настройки масштаба GUI в Minecraft. `xy()`, `rxy()`, `rwh()` и `anchor()`
работают относительно родительского контейнера.

Компонент не создаёт кнопку «Бросить», не размещает её и не резервирует
для неё место. Создание и обработка вашей кнопки остаются в вашем скрипте;
для запуска достаточно вызвать `dice.roll(...)`.
Сохранённое поведение «ЛКМ в любом месте GUI пропускает бросок» является
отдельным правилом ввода и не расширяет визуальные границы панели.

Для затемнения только панели не вызывайте `ui.background()`: этот штатный
метод затемняет весь экран, независимо от размера отдельных компонентов.

## Совместимость и свои текстуры

Старый `roll(durationMs)` сохранён: он проигрывает только кубик и удерживает
статичный кадр, без чисел и надписи. При заданном ID также отправляет событие
завершения (`dice.outcome = "none"`).

```javascript
dice.textures(
    "eoc:textures/gui/dice/d20_spin.png",
    "eoc:textures/gui/dice/d20_stop.png",
    "eoc:textures/gui/dice/d20_rest.png"
);
```

Этот метод заменяет только кубик. Новые текстуры должны использовать общий холст
480×600, с заранее заданным положением кубика; анимации — вертикальные полосы
480×(600×число кадров), с `width: 480`, `height: 600` в `.png.mcmeta`.
Цифры и надписи можно заменить ресурс-паком
по путям `assets/mappet/textures/gui/dice/gui_components_480x600/...`.
Для цифр используются готовые полноразмерные слои `position_1/digit_N.png`
и `position_2/digit_N.png`; для анимации числа — соответствующие `digit_N_fade.png`.
Объединённые атласы в сборку не включаются, так как дублируют эти слои.

Однозначное число на кубике и сложность смещаются к центру по видимым границам
последнего кадра, с сохранением двухпиксельной сетки ассетов.
При переходе к двум цифрам используются обе стандартные позиции без смещения.
В блоке «Параметр и навык» одна цифра всегда использует первую позицию рядом с плюсом;
вторая добавляется только для двузначного значения. Перелетает копия всего числа с плюсом.

Учитываются `frametime`, порядок и повторение `frames`, отдельные значения `time`,
явные `width` и `height`. Интерполяция кадров не поддерживается:
используйте `interpolate: false`. После эффекта показывается соответствующий
статичный слой с тем же последним кадром. При пропуске сразу выбираются статичные слои.
При F3+T кэш размеров и метаданных очищается.

Реализация использует существующие `UIComponent`, регистрацию типов,
NBT-передачу изменений, `GuiElement`, менеджер текстур и `GuiDraw`.
Завершение отправляется через тот же `UIContext.dirty()`, что и нажатие кнопки,
без нового вида пакетов или отдельной callback-системы.
